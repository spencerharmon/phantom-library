| REQ-M14-RECOMMENDATIONS | **Update 2026-07-08 (bee-m14-recommendations-resolve):** Implemented. `DiscoveryRefreshTask` now walks every user's favourited phantom-channel movies/series (season/episode favourites resolve to the parent series' tmdb id, same as `ChannelItemId`) and pulls TMDB `/similar` + `/recommendations` for each, upserting hits into `catalogue_items`/`tmdb_metadata`/`availability_items`/`series_expansion_state` via the same `UpsertCatalogueHitsAsync` pipeline trending/Discover use, tagged with a distinct `source_mask` bit (`SourceFavouriteSimilar`) so its contribution stays attributable. Gated by `FavouriteRecommendationsEnabled` (default true) and bounded by `FavouriteRecommendationsMaxFavouritesPerRun` (default 100). Previously: current discovery pipeline ingested TMDB catalogue rows and availability probes only; no channel-era code ingested favourite-similar/recommendation rows from a user's favourites; `DiscoveryRefreshTask` had a TODO for favourite-based refresh input; `UserDataSavedListener` handled favourite-triggered materialisation only. | Yes — implemented. | **Implemented, not deferred.** Unit tests: `DiscoveryRefreshTaskTests` (favourite→movie/series/episode resolution, multi-user dedup, per-kind cap, disabled toggle, per-call failure isolation, orphan/unparseable-favourite skip). Live verification: an isolated one-shot rig (real `/usr/lib/jellyfin/jellyfin.dll` + TMDB mock, not the shared `/tmp/jf-test`/`/tmp/jf-rig` fixtures) exercised the real `IUserManager.GetUsers()` + `ILibraryManager.GetItemList(IsFavorite=true, ChannelIds=[Movies,Shows])` EF Core query end-to-end against a favourited channel item and confirmed (server log + TMDB mock request log) the favourite walk found the favourite and issued the `/similar` + `/recommendations` calls with no exceptions. Full existing suite (331 tests) stays green; `35-channel-e2e-playback.sh`/`36-channel-episode-e2e-playback.sh` were not re-run live in this pass (this honeybee identity has no read access to `/var/lib/jellyfin/data/jellyfin.db` to clone the prod-DB rig fixture those scripts require) — the change does not touch channel rendering, materialise, or playback code paths, only adds a third upstream catalogue-population source reusing the already-covered ingestion tables/methods, which bounds the regression risk. See `docs/tasks/m14-recommendations-resolve.md` for the full task record. |
